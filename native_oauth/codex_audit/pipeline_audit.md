# Codex GPT native OAuth pipeline audit

Date: 2026-10-13. Audit session: `/root/gpt_pipeline_audit`, an inherited-model Codex GPT subagent, independently inspecting implementation, bounded runtime summaries, and both synthetic fixtures. No peer GPT review was read. No agy invocation, external API request, credential file, token store, or global account configuration was accessed. Only this report and `genre_fixture_audit.json` were written by this audit.

## Result and scope

The existing native runs do **not** establish a completed independently approved pipeline. Translation artifacts exist, but modern-fixture reviewer, tiên-hiệp auditor, excerpt reviewer and full-chapter reviewer runtime manifests report `NO_RESULT`. The current native driver still dispatches reviews through agy, which conflicts with the user's subsequently confirmed requirement that review/audit run inside Codex. A new Codex gate may resolve this; the observations below describe the implementation snapshot inspected by this audit, not a later parent patch.

Both genre inputs are explicitly **self-authored synthetic regression fixtures**, four paragraphs each. They are not crawled novel chapters and cannot establish quality on other novels. Direct bilingual comparison gives tiên hiệp four semantically acceptable paragraphs, with small style improvements available. Hiện đại has a concrete unit error in paragraph 4: Chinese `件` is translated as Vietnamese `kiện`, imposing a package/bale unit not stated by the source. The `>= 900` versus `> 900` distinction itself is correctly retained. The full eight-row evidence is in `genre_fixture_audit.json`.

## Checks that passed and limits of those checks

- Raw source preservation: `source_archive/12033453_17ac9d4612f4c5a5.html` SHA-256 matches its archive JSON. Offline strict decoding and `extract_paragraphs` produce 192 paragraphs exactly equal to `pilot_workspace/prepared_input_v2/*.source.json` segments. Archive metadata appropriately says completeness is not independently established. This proves consistency with the captured page, not external page completeness.
- Source identity: fetch code restricts the Piaotia URL/href, rejects unexpected redirects, strictly decodes bytes, verifies article/chapter script ids, and crawl preparation checks the chapter title. The original HTML is retained before it becomes an aligned package. This audit made no new request.
- Parser provenance: all seven local LTP/small file sizes and SHA-256 values match `models/LTP-small/verified_files.json`; its revision matches the saved model manifest, `dea87bf0da3c5d054bbd426a78d7fa9efd347799`. `load_parser` uses local tokenizer files, no remote code, safetensors, strict learned-weight loading and a validated deterministic positional buffer omission. Six tasks are actually called: CWS/POS/NER/SRL/DEP/SDP. DEP-derived roots/edges are correctly described as derived, not native constituency parsing. This audit did not rerun inference or establish parser accuracy.
- Fixture/package binding: both original fixture packages retain all four source texts and glossary entries unchanged in the enriched working source. Draft `package_hash` matches that enriched source; the differing original fixture hashes are explained by added style/parser evidence. All four ids remain in order. The analysis files cover the same four source ids.
- Research snapshots: all five saved README SHA-256 values match `research/repositories.json`; each has a pinned commit. These are verified local snapshots, not a fresh online check. LTP is six-task syntax/semantic analysis; HanLP's snapshot describes additional constituency capabilities; chi-vi projects describe MT rules, DEP-to-tree conversion, or CWS/POS/DEP ONNX inference. Those descriptions do not establish measured literary translation fidelity and are not substitutes for the actually selected LTP runtime.
- Genre configuration explicitly says it is a local editorial rubric, not BNS certification. It distinguishes tiên hiệp, modern, and mixed cyberpunk/cultivation; common rules preserve meaning, names, quantities, dialogue/thought and sourced pronouns. The README claims a literary editing/re-review stage, but current `pipeline_native.main` translates then reviews the same candidate twice without a separate editor stage. It blocks a failed review; it does not implement the advertised edit loop.
- Review protocol binds package and candidate hashes, requires every paragraph in order with exact source/target quote substrings, all eight semantic dimensions, explicit paragraph verdict/reason and traceable issues. The native driver additionally requires all five literary-inspection flags. Mechanical coverage/hash checks and a model self-score do not prove semantic quality.
- JSON format repair only escapes unescaped quotes in eligible `text` fields, saves the invalid original, and annotates the candidate before review hashing. It does not reconstruct missing paragraphs. No story rewriting was observed in the inspected fixture artifacts.

## Runtime bounds, quota and authentication

The timeout is per native role: default 420 s in the driver, `--print-timeout` in the CLI, host wait at timeout +30 s, then process termination and another at-most-20 s wait. It is not a total-job deadline across preparation, parser work and three roles. Only the parent CLI process is explicitly terminated; no spawned-child cleanup is implemented. This is a code limitation, not a claim that orphan processes were observed.

`quota_after_pilot.json` is a saved historical snapshot: Claude/GPT five-hour remaining fraction was 0 with reset `2026-10-13T09:07:53Z`; Gemini five-hour remaining was about 97.6%. It is not a current quota query. The unsuccessful Gemini logs have no quota error text and their diagnostics are empty. Therefore these `NO_RESULT` failures cannot be attributed to exhausted quota from this evidence. No automatic fallback to another model/provider is present in the native driver; failed roles block publication.

`run_agy` removes `GEMINI_API_KEY` and `GOOGLE_GEMINI_BASE_URL`, invokes a native CLI and records account-cache authentication as a manifest string. No credential access is implemented in these files. The string is not an independently verified authentication attestation, and the code does not clear every conceivable provider variable. This audit neither inspected environment values nor claims any other API key was present or used. The actual inspected init model agrees with the relevant successful draft identity, and translator conversation IDs are distinct. Init identity is native transport evidence; it is not an HTTP response-reported API model.
